# v1.17.3

Speaker diarization and subtitle segmentation are now on by default.

講者辨識與字幕切段改為預設開啟。

## Changed / 變更

- **Speaker diarization and subtitle segmentation ship on** ([python/whisperflow/config.py](python/whisperflow/config.py), [python/config/config.example.json](python/config/config.example.json), [locales/*/settings.json](locales/zh-TW/settings.json), [README.md](README.md)) — both shipped off in v1.17.0 while they were new and unverified, with the stated intention of revisiting once a long recording had been through them. That has now happened, and the case for each is that Whisper's raw output is not what most people want. Measured on a 64-minute talk: without segmentation, 7% of cues ran past the 7-second subtitle norm, 15% needed three lines or more, and the longest was 29.9 seconds and 447 characters — a wall of text on screen; with it, those become 3 cues, 0 cues and 10.6 seconds. Diarization costs about 7% of a run (255 s on that file) and downloads ~34 MB of models on first use, both of which are visible rather than silent: the download gets its own progress stage, and the stage chip names the pass while it runs. Segmentation's cost is word timestamps, which move segment boundaries slightly even where nothing is re-cut — but diarization turns those on too, so a default install does not pay it twice. **This changes output for new installs only.** `python/config/config.json` is gitignored and is never rewritten on upgrade, so an existing install keeps whatever it already had; either feature is still a single checkbox in Settings, and with them off the output is byte-identical to v1.16.7 as before.
  **講者辨識與字幕切段改為出貨即開啟** — v1.17.0 時兩者都因為還新、尚未驗證而預設關閉，當時也說明了等長錄影實測過再重新考慮。現在已經實測過了，而理由是：Whisper 的原始輸出並不是多數人想要的東西。在一場 64 分鐘的演講上量測：不切段時有 7% 的字幕超過 7 秒的業界規範、15% 需要三行以上，最長的一則是 29.9 秒、447 字元——在螢幕上就是一面牆；開啟後分別變成 3 則、0 則、10.6 秒。講者辨識約佔一趟執行的 7%（該檔案為 255 秒），首次使用會下載約 34 MB 的模型，而這兩項代價都是看得見的而非靜默的：下載有自己的進度階段，執行時階段標籤也會指名該道處理。切段的代價是逐字時間碼，它會讓分段邊界即使在沒被重新切到的地方也略微位移——但講者辨識同樣會開啟逐字時間碼，所以預設安裝不會付兩次。**這只改變全新安裝的輸出。** `python/config/config.json` 在版控忽略清單裡，升級時不會被改寫，所以既有安裝維持原本的設定；兩者在設定裡都仍然只是一個勾選框，關閉時輸出與 v1.16.7 一樣逐位元組相同。

## Tests / 測試

- **The tests that pinned the old defaults now pin the new ones, and the pipeline tests say what they want** ([python/whisperflow/tests/test_config.py](python/whisperflow/tests/test_config.py), [python/whisperflow/tests/test_transcriber.py](python/whisperflow/tests/test_transcriber.py), [tests/unit/settings-metadata.test.js](tests/unit/settings-metadata.test.js)) — five assertions covered the shipped default and were updated, including the widget-inference check, since `'True'` infers the same checkbox `'False'` did. Three pipeline tests had been inheriting the defaults rather than stating them, so flipping a default silently changed which stages they exercised; their fixture now pins both features off and each test that wants a stage asks for it. That is what the failures pointed at, and it makes them test what their names claim.
  **原本釘住舊預設的測試改釘新預設，管線測試則改為明說自己要什麼** — 有五處斷言涵蓋出貨預設並已更新，包含 widget 推斷那項（`'True'` 與 `'False'` 推斷出的都是同一種勾選框）。另有三項管線測試原本是「繼承」預設而非指明，所以翻轉預設會悄悄改變它們實際測到的階段；現在它們的 fixture 把兩個功能都釘成關閉，需要某個階段的測試自己要求。那正是失敗所指出的問題，修正後它們測的才是名稱宣稱的東西。
